## 0. КОНТЕКСТ

Я делаю закрытый Discord-сервер «Veritas»: секта правды с ролевой иерархией, уровнями допуска и архивом. У нас есть свой сайт; архив (досье, дела, тайны) живёт на сайте, а Discord — это общение и управление. Всё «тайное» — **игровое** (ники, персонажи, события внутри нашей игры/лора), без реальных личных данных.

Сейчас для сервера нужны Carl-bot, Ticket Tool, Logger и Wick/Sapphire. Я хочу **один собственный бот**, который заменяет всё это и знает нашу иерархию:

1. **Настройка сервера** (роли, права, категории, каналы) — идемпотентно.
2. **Верификация** (автороль при входе, анкета, одобрение).
3. **Тикеты** (допуск, жалоба, вопрос Совету) с транскриптами.
4. **Логи** (вступления, роли, сообщения, каналы, баны и т.д.).
5. **Защита от рейдов и от «сноса сервера»** (anti-raid, anti-spam, anti-nuke).
6. **Управление иерархией и наказаниями** (повышения, Лжец, Отлучённый).
7. **Мост с сайтом** (фаза 7): HTTP API, чтобы сайт узнавал уровень допуска человека и публиковал уведомления в #архив.

В репозитории лежит **`veritas_server.py`** — рабочий эталонный скрипт, который уже создаёт роли-права и каналы с точными правами на каждый канал. Он проверен симуляцией прав. **Это источник истины по структуре и правам.** Не выбрасывай его логику: перенеси в модуль бота (см. §3 и §4) и сохрани поведение.

## 1. ПРАВИЛА РАБОТЫ (обязательно)

1. **Сначала прочитай** `veritas_server.py` и этот файл целиком. Потом составь короткий план по фазам и начинай.
2. **Не выдумывай API.** Для discord.py используй актуальную документацию (Context7 или официальные доки). Если не уверен в сигнатуре (например `Guild.edit(invites_disabled=...)`, `create_forum`, `Member.timeout`) — проверь по доке или интроспекцией `inspect.signature`, а не по памяти.
3. **Работай фазами** (§17). После каждой фазы: тесты зелёные → коммит с понятным сообщением → короткий отчёт мне (что сделано, что проверено, что осталось).
4. **Секреты:** токен только из `.env`/переменных окружения. Никогда не коммить `.env`, не печатать токен в логи. Добавь `.gitignore`, `.env.example`.
5. **Ничего необратимого без `--confirm`/подтверждения:** бот и скрипты настройки **ничего не удаляют** (каналы, роли, сообщения). Исключения — только явные команды наказаний, описанные ниже.
6. **Идемпотентность:** повторный запуск настройки обновляет, а не дублирует. Есть режим `--dry-run`, который печатает план изменений и ничего не меняет.
7. **Тексты для пользователей — по-русски**, понятные, в атмосфере секты, но без перегиба. Код, комментарии, имена модулей — английский допустим; докстринги и README — русский.
8. **Тесты обязательны** для всей чистой логики (расчёт прав, маппинг допусков, правила повышения, детектор рейдов с поддельными часами). Живой Discord ты проверить не сможешь — не пиши, что «проверил на сервере». Честно отмечай, что требует ручной проверки мной.
9. **Никаких лишних зависимостей.** Минимум библиотек, фиксируй версии в `requirements.txt`.
10. Если требование неоднозначно — выбери самый безопасный вариант, запиши решение в `docs/DECISIONS.md` и иди дальше. Спрашивай меня только если без ответа нельзя продолжить.

## 2. СТЕК И АРХИТЕКТУРА

- **Python 3.11+**, **discord.py 2.x** (слэш-команды `app_commands`, persistent views, modals).
- **SQLite** через `aiosqlite` (файл в томе `data/`). Миграции: простая таблица `schema_version` + SQL-файлы по порядку.

Роли **не переименовывай и не перекрашивай**. Ищи по ID; для Основателя и Последователя — по названию (подстрока «основател» / «последоват», без учёта регистра), Последователя создай, если не найден. Все ID/названия — в `config.py`, не размазывай по коду.

### 3.2 Права ролей на сервере
Взять **дословно** из `ROLE_PERMS` в `veritas_server.py`. Главное правило безопасности: «Администратор», «Управление сервером», «Управление вебхуками» — **только у Основателя**. Управление каналами — **только у Главы Совета**. Если у другой роли есть «Администратор» — бот предупреждает в консоль и в #логи, но сам не снимает.

### 3.3 Каналы и права
Взять структуру и права из `STRUCTURE` в `veritas_server.py` (16 каналов, у каждого свои: кто видит, кто пишет, реакции, ветки, медленный режим, ограничения для Лжеца). Особенности, которые нужно сохранить:

- `✅┃верификация` скрыт от Последователя/Посвящённого/Архивариуса (прошедшие его не видят), виден Незнакомцу, Доверенным, Совету.
- `🔎┃расследования` — форум с тегами; дела создают Архивариус+Совет, отвечать в ветках могут все, кто видит.
- `📋┃анкеты` — новый канал в категории ТАЙНЫ (видят Доверенный+), куда падают анкеты новичков. Пишет только бот.
- Лжец: в `💬┃общий-чат` нет файлов/ссылок/веток; в голосовом нет стрима.
- `📊┃логи` — писать может только бот.
- Канал `📢┃новости` — тип «Объявления» только если на сервере включено «Сообщество»; иначе обычный текстовый (с предупреждением).

Дополнительно бот создаёт **категорию `🎫 ТИКЕТЫ`** (скрыта от всех, кроме Совета и бота), где живут каналы тикетов (§6).

### 3.4 Маппинг допусков (`clearance.py`)

```
0 — Отлучённый
1 — Незнакомец
2 — Последователь          (Лжец ограничивает потолок до 2)
3 — Посвящённый
4 — Доверенный, Архивариус
5 — Член Совета, Глава Совета, Основатель
```
Допуск человека = максимум по его ролям; если есть Отлучённый → 0; если есть Лжец → `min(уровень, 2)`. Функция чистая, покрыта тестами. Эта же функция используется API сайта (фаза 6).

## 4. ФАЗА 1 — SETUP (`cogs/setup.py`, `permissions.py`, `config.py`)

**Цель:** перенести `veritas_server.py` в модули бота без потери логики.

- Слэш-команда `/setup run` (только Основатель/Глава Совета) и `/setup dry-run`: показывает план (что создаст/обновит) ephemeral-сообщением.
- Консольный запуск: `python -m veritas setup [--dry-run]` (чтобы можно было настроить сервер до запуска бота как сервиса).
- Идемпотентно: категории/каналы ищутся сначала по сохранённому ID (таблица `managed_channels`), затем по названию; существующие обновляются (overwrites, slowmode), новые создаются.
- Выставляет базовые права `@everyone` (как `SAFE_EVERYONE`).
- **Порядок ролей:** бот выстраивает позиции известных ролей в правильном порядке (Основатель → … → Отлучённый), **только в пределах позиций ниже собственной роли**. Если не может — сообщает, что нужно перетащить вручную.
- Публикует и **закрепляет** стартовые тексты: правила в `#правила`, «о секте» там же или в отдельном embed, шаблон приёма в `#приём-материалов`, панель верификации в `#верификация`, панель тикетов в `#заявки`. Сообщения бот отслеживает по ID в БД и при повторном запуске **редактирует**, а не дублирует.
- Выбор «источник истины для структуры»: `permissions.py` содержит чистую функцию `compute_overwrites(config) -> dict`, без обращений к Discord, чтобы её можно было тестировать.
- **Тест-симулятор прав**: перенеси симуляцию (как в моей проверке) в `tests/test_permissions.py`: для 9 персонажей (Незнакомец, Последователь, Лжец, Посвящённый, Доверенный, Архивариус, Член Совета, Глава, Отлучённый) × 16 каналов проверь матрицу «не видит / читает / пишет». Эталонная матрица должна быть зафиксирована в тесте.

**Приёмка фазы 1:** `pytest` зелёный; `--dry-run` печатает план; матрица прав совпадает с эталоном (Незнакомец видит только правила и верификацию; Отлучённый только апелляции; Лжец без файлов/ссылок; Член Совета не пишет в правила/новости/заявки).

## 5. ФАЗА 2 — ВЕРИФИКАЦИЯ (`cogs/verification.py`)

Поток:

1. **Вход:** `on_member_join` → выдать роль **Незнакомец**. Ботов не трогать. Если у человека в БД есть метка Отлучённого (после перезахода) — вернуть Отлучённого.
2. **Панель** в `#верификация`: embed + кнопка **«Пройти ритуал входа»** (persistent view, `custom_id` фиксированный, `timeout=None`, регистрируется в `setup_hook`).
3. Нажатие → **Modal** (до 5 полей, берём 3–4): 
   - «Как тебя зовут в игре/в общине?» (ник/персонаж),
   - «Откуда ты узнал о Veritas?»,
   - «Почему хочешь вступить?» (параграф, мин. 30 символов),
   - «Согласен соблюдать правила? (напиши «да»)».
4. **Анти-абьюз:** кулдаун на повторную подачу (по умолчанию 10 минут после отказа — 24 часа), максимум 3 попытки в сутки, мин. возраст аккаунта (по умолчанию 3 дня, настраивается; моложе — автоматически в «ручную проверку» с пометкой ⚠️), проверка длины/мусора.
5. Анкета уходит embed-ом в **`#анкеты`** с кнопками **«✅ Принять»** / **«❌ Отклонить»** (persistent, состояние в БД, привязка к `application_id`).
   - Нажать могут **Доверенный и выше**. Остальным — ephemeral отказ.
   - **Принять:** снять Незнакомца, выдать **Последователя**, ЛС человеку (если ЛС закрыты — ничего страшного), запись в логи, embed анкеты помечается «принято кем/когда» и кнопки отключаются.
   - **Отклонить:** модал с причиной (необязательно), ЛС с причиной, кулдаун 24 ч, роль остаётся Незнакомец.
   - Нельзя принять анкету, если человек уже вышел с сервера (аккуратная обработка).
6. Режим в конфиге: `VERIFY_MODE = "manual"` (по умолчанию, решает Доверенный) или `"auto"` (авто-выдача Последователя при прохождении проверок). Реализуй оба.
7. Если человек вышел и вернулся — состояние анкеты не теряется; если был принят ранее — можно вернуть Последователя автоматически (настройка `RESTORE_ON_REJOIN`, по умолчанию выкл).

**Приёмка:** юнит-тесты на правила анти-абьюза, кулдауны, права на кнопки (мокни `interaction`), переходы состояний анкеты (`pending → accepted/rejected`, повторное нажатие безопасно).

## 6. ФАЗА 3 — ТИКЕТЫ (`cogs/tickets.py`)

- Панель в `#заявки`: три кнопки (или Select): **«🔑 Заявка на допуск»**, **«⚠️ Жалоба»**, **«❓ Вопрос Совету»**.
- Нажатие → создаётся **приватный текстовый канал** `тикет-0042-ник` в категории `🎫 ТИКЕТЫ` (канал, не приватная ветка — надёжнее по правам). Видят: автор, обработчики, бот.
  - Обработчики: «допуск» → Доверенный+; «жалоба» и «вопрос» → Член Совета+.
- Лимиты: не больше 1 открытого тикета каждого типа и не больше 3 всего на человека; кулдаун 30 секунд.
- Первое сообщение в тикете: embed с типом, автором, инструкцией и кнопками **«🙋 Взять»** (claim), **«🔒 Закрыть»**.
- Закрытие: подтверждение, причина (необязательно). После закрытия:
  1. собрать **транскрипт** (текст `.txt`/`.html`: время, автор, текст, вложения-ссылки),
  2. отправить транскрипт в `#логи` и автору в ЛС (если открыты),
  3. записать в БД,
  4. удалить канал тикета через 10 секунд (**это единственное допустимое удаление каналов ботом**, только каналов тикетов, созданных самим ботом и найденных в БД).
- Команды: `/ticket add @user`, `/ticket remove @user`, `/ticket close [причина]`, `/ticket rename`.
- Автозакрытие по неактивности (по умолчанию 7 дней) с предупреждением за 24 часа.
- Для «допуска»: кнопки в тикете **«Выдать допуск…»** для обработчиков не делай — повышения идут через `/rank` (§9), но бот подсказывает команду.
- Для Отлучённых тикеты недоступны (у них #апелляции).

**Приёмка:** тесты на лимиты, права доступа канала (compute overwrites), нумерацию, закрытие/транскрипт (на моках).

## 7. ФАЗА 4 — ЛОГИ (`cogs/logs.py`)

Все логи — embed-ами в `#логи` (пишет только бот). Цвета: зелёный — вход/добавление, красный — удаление/бан, жёлтый — изменение, синий — инфо.

Что логировать:

- **Участники:** вход (аккаунт создан когда, пригласивший если определим), выход, бан/разбан, кик, тайм-аут (+ снятие), смена ника, **смена ролей** (кто выдал/снял — через audit log с обработкой ошибок и таймаутов).
- **Сообщения:** удаление и редактирование (старое/новое содержимое, автор, канал, вложения). **Приватность:** не логировать содержимое из каналов с допуском 5 (`⚫┃совет`, `⚖️┃суд-и-допуски`, `📊┃логи`) и из тикетов — только факт. Содержимое не хранить в БД дольше кэша discord.py; для 100% удаления «до запуска бота» логируй как «сообщение не в кэше».
- **Сервер:** создание/удаление/изменение каналов, ролей (особенно изменения прав), эмодзи, вебхуков, приглашений, смена настроек.
- **Голос:** вход/выход/перемещение (по умолчанию выкл. флагом).
- **События бота:** принятие/отклонение анкет, тикеты, повышения, наказания, срабатывания anti-raid.
- Аудит-логи подтягивать аккуратно: кэш последних записей, ограничение запросов, чтобы не упереться в рейтлимит.
- **Очередь отправки** с батчингом и ретраями при 429: логи не должны терять события при всплесках.
- Команда `/logs test` (Совет+) — тестовое сообщение; `/logs toggle <категория>` — вкл/выкл категорий (в БД).
- Логи не должны логировать самих себя (защита от петли).

**Приёмка:** юнит-тесты на форматирование embed-ов и фильтр приватных каналов.

## 8. ФАЗА 5 — ЗАЩИТА (`cogs/antiraid.py`)

Все пороги в `config.py` и меняются командой `/raid config` (Совет+). Участники с допуском ≥ 4 (и роль-исключения) защитой **не наказываются**, кроме anti-nuke.

### 8.1 Anti-raid (вход)
- Скользящее окно: если за **N входов за T секунд** (по умолчанию 8 за 20 с) → включается **режим локдауна**.
- Локдаун: 
  1. оповещение в `#логи` и `#совет`, пинг Совета;
  2. новые входящие автоматически получают **таймаут** (или кик по настройке) пока локдаун активен;
  3. при поддержке API — временно **отключить создание приглашений** (`invites_disabled`) и/или поднять уровень верификации сервера, запомнив прежние значения для отката (проверь в доке, что параметры существуют; если нет — пропусти и запиши в `DECISIONS.md`);
  4. кнопки в оповещении: «Снять локдаун», «Кикнуть всех, вошедших во время рейда» (с подтверждением).
- `/lockdown on|off|status` (Совет+). Авто-снятие через N минут без новых всплесков.
- Фильтры при входе: возраст аккаунта (<порога → таймаут + пометка), подозрительные ники (ссылки, `discord.gg`, массовые одинаковые шаблоны), аватар по умолчанию + новый аккаунт — повышает «подозрительность» (скоринг, не бан).

### 8.2 Anti-spam (сообщения)
Для ролей **Незнакомец, Последователь, Лжец, Посвящённый**:
- флуд (>X сообщений за Y секунд) → удаление + таймаут по лестнице (предупреждение → 10 мин → 1 час);
- одинаковые сообщения в нескольких каналах;
- приглашения на другие серверы и ссылки (разрешены только Доверенный+ и белый список доменов вашего сайта);
- массовые упоминания (`@everyone`, >5 упоминаний);
- Каждое срабатывание — в логи с причиной.

### 8.3 Anti-nuke (защита от сноса)
Следить за аудит-лог/событиями: если **один пользователь (не Основатель)** за короткое окно (по умолчанию 60 с) совершает **≥ 3** деструктивных действия — удаление каналов, удаление ролей, массовые баны/кики, создание вебхуков, смена прав `@everyone`:
- немедленно **снять с него все роли с опасными правами** (в пределах позиции бота) и выдать таймаут, если возможно;
- оповестить Основателя в ЛС и Совет в `#совет`/`#логи`;
- бот **не «чинит» удалённое сам** (ничего не пересоздаёт без команды), но при следующем `/setup run` структура восстановится.
- Не ломать работу самого бота и Основателя.

### 8.4 Защита структуры
- Если у роли появилось право «Администратор»/«Управление сервером» (кроме Основателя) — оповещение в `#совет` + кнопка «Откатить права» (Совет+).
- Если `@everyone` получил право просмотра закрытых категорий — оповещение.

**Приёмка:** тесты детектора на поддельных часах (рейд срабатывает/не срабатывает на границе, откат локдауна, исключение для допуска ≥ 4), тесты anti-nuke на потоке событий.

## 9. ФАЗА 6 — ИЕРАРХИЯ И НАКАЗАНИЯ (`cogs/ranks.py`)

### 9.1 Правила «кто что может выдать»
**Нельзя выдать роль, равную или выше своей. Нельзя трогать того, кто равен или выше.**

| Переход | Кто может |
|---|---|
| Незнакомец → Последователь | Доверенный+ (обычно через анкету) |
| Последователь → Посвящённый | Архивариус+ |
| → Доверенный / Архивариус | Член Совета+ (в журнал с причиной) |
| → Член Совета | Основатель (и Глава Совета по настройке `HEAD_CAN_APPOINT_COUNCIL`) |
| → Глава Совета | Только Основатель |

Команды: `/rank promote @user`, `/rank demote @user`, `/rank set @user <роль>` (все с причиной, пишут в `#суд-и-допуски` журнал: кто/кому/что/когда/почему), `/rank info @user` (допуск, роли, дата вступления, активные дни, метки).

### 9.2 Активность
Таблица `activity(user_id, day, messages)` — считаем **только количество сообщений в день**, содержимое не храним. `/rank info` показывает «активных дней». Для перехода Последователь→Посвящённый подсказка «7 активных дней» (не блокировка, а подсказка для решающего).

### 9.3 Наказания
- `/liar @user <причина>` (Член Совета+): снимает все роли **выше Последователя**, выдаёт **Лжец**, сохраняет снятые роли в БД (для `/restore`), пишет в журнал, ЛС человеку.
- `/exile @user <причина>` (Член Совета+): снимает **все** управляемые роли, оставляет только **Отлучённый**, сохраняет прежние роли.
- `/restore @user` (Член Совета+): снимает метку и возвращает сохранённые роли (кроме ролей, которых уже нет).
- `/timeout`, `/untimeout` как обёртки над таймаутом (Доверенный+; лимит длительности для Доверенных, например до 24 часов).
- **Отлучённый:** при повторном входе после выхода/кика бот снова выдаёт Отлучённого (БД).
- Роли-метки **никогда** не накладываются на Основателя и Совет: попытка → ephemeral-отказ.
- Лесенка: предупреждение → тайм-аут → Лжец → Отлучение → бан. Бот напоминает её в подсказках, но не заставляет.
- `/warn @user <причина>`, `/warns @user` — предупреждения в БД, при 3 предупреждениях — подсказка Совету.

**Приёмка:** юнит-тесты на матрицу «кто может выдавать что» и на `/liar`/`/exile`/`/restore` (на моках: роли снимаются и возвращаются, защита Совета и Основателя).

## 10. ФАЗА 7 — МОСТ С САЙТОМ (`veritas/api/`, `cogs/archive.py`)

Сайт хранит архив и проверяет допуск. Бот даёт API (FastAPI), закрытое токеном `API_TOKEN` (Bearer, сравнение через `hmac.compare_digest`, rate-limit, слушать только указанный хост):

- `GET /api/v1/clearance/{discord_id}` → `{"discord_id": ..., "level": 0..5, "roles": [...], "is_liar": bool, "is_exiled": bool}`. Использует ту же функцию из `clearance.py`. Если человека нет на сервере → `level: 0`, `member: false`.
- `POST /api/v1/archive/announce` → публикует embed в `#архив`: номер («ДОСЬЕ-0042»), название, гриф (2–5), ссылка, достоверность, автор. Валидация входа (pydantic), ссылки только на разрешённые домены (`ALLOWED_SITE_DOMAINS`).
- `POST /api/v1/vault/announce` → пост в `#хранилище` (уровень 4+) о новом защищённом материале **без самих ключей** (ключи и пароли через бота не передаются никогда).
- Команда `/archive announce` — то же самое вручную для Архивариуса.
- HTTPS и reverse-proxy — на моей стороне, в README опиши, как поставить за nginx/Caddy. По умолчанию слушать `127.0.0.1`.
- Документируй API в `docs/API.md` с примерами `curl`.
- Предусмотри будущую интеграцию «вход на сайт через Discord OAuth»: сайт после OAuth зовёт `/clearance/{id}`, так что отдельные коды допуска можно будет заменить проверкой роли. Реализовывать OAuth на сайте НЕ нужно — только API.

## 13. ТЕКСТЫ (используй как основу, можно слегка улучшить)

**`#правила`** (embed, закреплён):
1. Здесь всё игровое: ники, персонажи, события нашей игры и лора. Реальные имена, адреса, фото, личные переписки и чужие личные данные **запрещены**.
2. Материалы выше твоего допуска не выносим и не пересказываем. Слив = метка 🐍 Лжец, потеря допуска, суд.
3. Ложь в архиве — тоже ложь. Источники указываем честно.
4. Уважаем друг друга. Игровая вражда не повод для реальных оскорблений и травли.
5. Реклама, чужие приглашения и спам запрещены.
6. Решения Совета обсуждаются в тикетах, а не в общем чате.
7. Допуск можно повысить вкладом в архив, а потерять — нарушением.
8. Незнание правил не освобождает. Совет может изменить их, объявив в #новости.

**`#верификация`** (embed): «Добро пожаловать, Незнакомец. Veritas хранит правду, но не для всех. Прочитай правила в #правила и нажми кнопку ниже. Ответь честно: Доверенные прочитают твою анкету и решат, откроется ли для тебя дверь.»

**Ответ на анкету:** принято — «Ритуал пройден. Теперь ты Последователь. Тебе открыта Община и Библиотека.»; отклонено — «Анкета отклонена. Причина: {reason}. Ты можешь подать её снова через {cooldown}.»

**`#заявки`** (embed): «Нужна помощь Совета? Выбери тип обращения. Мы откроем приватный канал, видимый только тебе и тем, кто решает.»

**Шаблон `#приём-материалов`:** взять из `veritas_server.py` (`INTAKE_TEMPLATE`).

Все тексты вынести в `veritas/content/` и сделать единообразный стиль embed-ов (цвета из `config.py`).

## 14. ТЕСТЫ И КАЧЕСТВО

- `pytest -q` должен проходить в чистом окружении без доступа к Discord.
- Обязательные тестовые наборы: матрица прав каналов (9 ролей × 16 каналов), маппинг допусков, матрица повышений, анти-абьюз верификации, лимиты тикетов, детектор рейдов (поддельные часы), anti-nuke, `/liar`/`/exile`/`/restore`, фильтр приватных каналов в логах, валидация API и токена.
- `ruff check` без ошибок.
- Обработка ошибок: все слэш-команды и кнопки ловят `discord.Forbidden`/`HTTPException` и отвечают человеку понятным ephemeral-сообщением, ошибки пишутся в консольный лог и (кратко) в `#логи`. Бот не падает от одного плохого события.
- Рейтлимиты: не делать массовые операции в цикле без пауз; для настройки каналов — аккуратные `await asyncio.sleep` между созданиями.
- Логирование: стандартный `logging`, без токена и без содержимого сообщений Совета.
