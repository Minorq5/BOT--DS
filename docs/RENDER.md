# Запуск на Render

## Как это работает и почему именно так

У Render бесплатный тариф есть только у **Web Service**. У него два ограничения
([render.com/docs/free](https://render.com/docs/free)):

1. **Засыпает через 15 минут**, если на его адрес не пришло ни одного HTTP-запроса. Discord-боту
   входящие запросы не нужны, поэтому без мер он бы засыпал.
2. **Файлы стираются** при каждом деплое, перезапуске и засыпании, постоянных дисков нет. Обычная база
   SQLite пропадала бы вместе с анкетами, тикетами, метками Отлучённых и предупреждениями.

Что делает бот:

| Проблема | Решение |
|---|---|
| Render ждёт открытый порт | бот слушает `$PORT` и отвечает на `/` и `/health` |
| Засыпание | **само-пинг**: раз в 10 минут бот запрашивает свой адрес `RENDER_EXTERNAL_URL` |
| Подстраховка само-пинга | **внешний пинг** (UptimeRobot, бесплатно) — ниже, шаг 5 |
| Стирание файлов | **копия базы в Discord**: скрытый канал `🗄┃бэкап-бота`, бот обновляет копию раз в 5 минут и при остановке, а при старте скачивает её обратно |
| Остановка при деплое | бот ловит SIGTERM и перед выходом сохраняет копию |

Бесплатных часов Render — 750 в месяц на аккаунт. Одному сервису, работающему круглосуточно, этого хватает
(≈ 744 ч). **Второй бесплатный сервис в том же аккаунте не заводи** — часы кончатся и всё уснёт до
следующего месяца.

## Шаги

### 1. Подготовка в Discord

Сделай пункты 1.1–1.3 из README: создай бота, включи intents, пригласи бота и подними его роль.

### 2. Создать сервис

**Вариант А — Blueprint (проще).** В репозитории есть `render.yaml`.
Dashboard → **New → Blueprint** → выбери репозиторий → Render спросит секреты:

- `DISCORD_TOKEN` — токен бота;
- `GUILD_ID` — ID сервера;
- `API_TOKEN`, `ALLOWED_SITE_DOMAINS` — только если нужен мост с сайтом, иначе оставь пустыми.

**Вариант Б — вручную.** Dashboard → **New → Web Service** → репозиторий, затем:

| Поле | Значение |
|---|---|
| Language | Python 3 |
| Branch | ветка с ботом |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python -m veritas` |
| Instance Type | Free |
| Health Check Path (Advanced) | `/health` |

Environment → переменные:

```
PYTHON_VERSION=3.12.8
DISCORD_TOKEN=...
GUILD_ID=...
DB_BACKUP_TO_DISCORD=true
DB_BACKUP_MINUTES=5
KEEPALIVE_MINUTES=10
```

`PORT` и `RENDER_EXTERNAL_URL` Render задаёт сам — их добавлять не нужно.

### 3. Проверить запуск

В логах сервиса (Logs) должно быть:

```
Резервная копия в Discord: копии в Discord ещё нет — начинаю с пустой базы
HTTP слушает 0.0.0.0:10000 (только проверка здоровья)
Само-пинг https://veritas-bot.onrender.com каждые 10 мин
Вошёл как Veritas#1234 ...
```

Открой `https://<твой-сервис>.onrender.com/health` — ответ вида `{"ok":true,"discord_ready":true,...}`.

### 4. Настроить сервер

В Discord: `/setup dry-run` → проверить план → `/setup run`. Консольную команду `python -m veritas setup`
на Render запускать не нужно.

Через 5 минут появится скрытый канал `🗄┃бэкап-бота` с одним сообщением. **Не удаляй его** —
из него бот восстанавливает базу. Его видит только бот (и Основатель как администратор).
Сохранить копию немедленно — `/backup`. Состояние копии показывает `/status`.

### 5. Внешний пинг — подстраховка (рекомендуется)

Само-пинг не разбудит сервис, если тот всё-таки уснул: например, Render перезапустил его, а Discord
в этот момент был недоступен. Внешний пингер делает работу независимо от бота:

1. Зарегистрируйся на <https://uptimerobot.com> (бесплатно).
2. **Add New Monitor** → тип **HTTP(s)** → URL `https://<твой-сервис>.onrender.com/health` →
   интервал **5 минут**.
3. Бонус: письмо на почту, если бот упал.

Подойдёт любой аналог: cron-job.org, Better Stack и т. п.

## Что важно знать

- **Деплой = перезапуск.** Render сначала поднимает новую копию бота, потом останавливает старую.
  Около минуты работают обе: возможны двойные записи в `#логи`. Изменения, сделанные в эту минуту,
  могут потеряться. Перед деплоем выполни `/backup`, а пушить лучше, когда на сервере тихо.
- **Сбой Discord при старте.** Если при запуске не удалось скачать копию (Discord недоступен), бот
  **выключает сохранение** до перезапуска, чтобы пустая база не затёрла хорошую копию. В `/status`
  это видно как «⚠️ выключена». Лечится перезапуском: Dashboard → Manual Deploy → Restart.
- **Размер копии.** Лимит вложения Discord для ботов — 10 МБ. Бот ругнётся в логах, если база дорастёт до 9 МБ.
  При текущем объёме данных это годы работы.
- **Мост с сайтом.** Если задан `API_TOKEN`, API доступно по `https://<сервис>.onrender.com/api/v1/...`
  (HTTPS даёт Render, nginx не нужен). Методы — в [API.md](API.md).

## Если готов платить (надёжнее)

Тариф **Starter (~$7/мес)** не засыпает, само-пинг не нужен. К нему можно подключить **Persistent Disk**
($0.25/ГБ в месяц):

- Disk → Mount Path `/var/data`;
- переменная `DB_PATH=/var/data/veritas.db`;
- `DB_BACKUP_TO_DISCORD=false`, `KEEPALIVE_MINUTES=0`.

С диском база хранится как обычно, без копий в Discord. Минус: у сервисов с диском нет деплоя без
простоя, бот будет недоступен секунд 30 при каждом обновлении.
