# Принятые решения

Здесь записаны места, где ТЗ (`PROMPT.md`) допускало несколько толкований, и что выбрано.
Правило выбора — самый безопасный вариант.

## Фаза 0 — каркас

- **D-001. Чистая логика вне cogs.** Помимо `permissions.py` и `clearance.py` чистые (без Discord)
  правила вынесены в `veritas/logic/` (анти-абьюз, тикеты, рейды, спам, anti-nuke, логи). Cogs
  только связывают их с Discord. Так всё тестируется без сети.
- **D-002. Без python-dotenv.** `.env` читает крошечный загрузчик в `config.py` (не перезаписывает
  уже заданные переменные). Docker читает `.env` через `env_file`.
- **D-003. Владелец сервера = Основатель.** Даже если роли «Основатель» нет, владелец сервера
  считается допуском 5 и проходит проверки «только Основатель».
- **D-004. Таблицы сверх §11:** `settings` (ключ/значение: сохранённый ID роли Последователя,
  переопределения порогов `/raid config`) и `liars` (метка Лжеца для восстановления при перезаходе,
  аналог `exiled`). В `tickets` добавлены `last_activity`, `inactivity_warned`, `closed_by`,
  в `applications` — `flags`, `reason`, `channel_id`.
- **D-005. Время в БД** — UNIX-секунды (UTC), `REAL`.
- **D-006. Команды регистрируются только на сервере `GUILD_ID`** (`copy_global_to` + `sync(guild=…)`):
  появляются сразу, бот не работает на чужих серверах.
- **D-007. Message Content Intent.** Если Discord отклонил привилегированные intents, бот
  перезапускается без Message Content и предупреждает; анти-спам по тексту и содержимое в логах
  отключаются. Без Server Members Intent бот не запускается (объясняет, что включить).

## Фаза 1 — настройка

- **D-101. Оверрайт бота в каждом канале.** В эталонном скрипте бот работал с «Администратором».
  В штатном режиме (без него) бот не увидит закрытые каналы и не сможет писать в `#логи`/`#анкеты`,
  поэтому `compute_overwrites` добавляет персональный оверрайт бота (`config.BOT_OVERWRITE`). На
  права людей это не влияет — матрица 9×16 совпадает с эталоном.
- **D-102. Overwrites канала заменяются целиком**, как в эталоне (`channel.edit(overwrites=…)`):
  ручные оверрайты на управляемых каналах при `/setup run` пропадут. Структура — источник истины.
- **D-103. Описание канала** заполняется, только если пустое (не перетираем ручные правки).
- **D-104. Канал, найденный по названию в другой категории**, переносится в нужную категорию.
- **D-105. Порядок ролей.** Бот двигает только известные роли ниже своей и только между позициями,
  которые они уже занимают (посторонние роли не сдвигаются). Остальное — подсказка «перетащи вручную».
  Лжец и Отлучённый стоят внизу, как в таблице §3.1.
- **D-106. `/panel`** — отдельная команда (Совет+), переопубликует/редактирует закреплённые тексты
  и панели без полной настройки. `/setup run` и `/setup dry-run` — только Основатель/Глава.
- **D-107. Категория `🎫 ТИКЕТЫ`** входит в `STRUCTURE` (без каналов) и создаётся `/setup`.
- **D-108. Канал объявлений.** Без «Сообщества» создаётся текстовым с предупреждением; если
  «Сообщество» включили позже, `/setup run` переводит его в тип «Объявления».
- **D-109. Правила и «о секте»** — два embed-а в одном закреплённом сообщении `#правила`.
  Ссылка на сайт берётся из `SITE_URL` (необязательно).
- **D-110. Роль выше роли бота** не редактируется (Discord запрещает) — в отчёте подсказка.

## Фаза 2 — верификация

- **D-201. Кнопки анкеты** — `DynamicItem` с `custom_id` вида `veritas:app:accept:<id>`: переживают
  перезапуск бота, состояние берётся из БД по `application_id`.
- **D-202. Решение атомарно**: `UPDATE … WHERE id = ? AND status = 'pending'`. Двойное нажатие
  двумя Доверенными одновременно — второй получает «уже решена». Если выдать роль не удалось
  (нет прав) — анкета возвращается в `pending`.
- **D-203. Ошибки в анкете** (короткий ответ, мусор, нет «да») не считаются попыткой — человек
  получает подсказку и может исправить. Попыткой считается только принятая к рассмотрению анкета.
- **D-204. Кулдаун 10 минут** действует между любыми подачами; после отказа — 24 часа.
  Лимит «3 в сутки» — по скользящему окну 24 часа.
- **D-205. Молодой аккаунт** (< 3 дней) — даже в режиме `auto` анкета идёт на ручную проверку с ⚠️.
- **D-206. Метка Лжеца при перезаходе** тоже возвращается (таблица `liars`), иначе метку можно
  «сбросить» выходом с сервера. Отлучённому при перезаходе выдаётся только «Отлучённый».
- **D-207. Мусор** определяется эвристикой (мало букв, повтор символа, «слово» из 25+ букв).
  Ник проверяется мягко (только длина и повторы), чтобы не отсекать ники вроде «007».
- **D-208. Решённая анкета**: embed перекрашивается (зелёный/красный), добавляется «кто/когда»,
  кнопки заменяются одной неактивной кнопкой со статусом.

## Фаза 3 — тикеты

- **D-301. Обработчики** определяются по допуску: «допуск» → уровень 4+ (Доверенный, Архивариус,
  Совет, Глава, Основатель), «жалоба» и «вопрос» → уровень 5. Лжец/Отлучённый обработчиками не бывают.
- **D-302. Нумерация** — `MAX(number)+1` под `asyncio.Lock`; если канал создать не удалось,
  зарезервированная запись удаляется из БД (номер освобождается).
- **D-303. Закрытие** — через модальное окно с необязательной причиной (отправка формы = подтверждение).
  Закрыть могут автор и обработчики; `/ticket add|remove|rename` — только обработчики.
- **D-304. Транскрипт** — `.txt` (время UTC, автор, текст, ссылки на вложения, отметка embed-ов),
  до 5000 сообщений. Уходит в `#логи` и автору в ЛС.
- **D-305. Удаление канала** — фоновая задача через 10 с, только если канал есть в таблице `tickets`
  **и** лежит в категории `🎫 ТИКЕТЫ`. Любой другой канал бот не удаляет.
- **D-306. Неактивность** считается по сообщениям людей (сообщения бота не продлевают тикет).
  Проверка — раз в 30 минут: предупреждение за 24 ч, закрытие через 7 дней.
- **D-307. Отлучённые** не могут открыть тикет (и не видят `#заявки`).

## Фаза 4 — логи

- **D-401. «Кто сделал»** берётся из события `on_audit_log_entry_create` (Discord присылает его сам,
  нужен только доступ к журналу аудита). Записи хранятся в памяти 60 с (`AuditCache`). Если записи
  нет — один запрос журнала, не чаще раза в 2 с, с таймаутом 5 с; ошибка → «не определён».
- **D-402. Очередь логов**: до 5000 событий, батчи по 10 embed-ов (лимит Discord) с ожиданием до 1 с,
  ретраи при 429/5xx с экспоненциальной паузой (до 5 попыток). Файлы (транскрипты) — отдельными
  сообщениями. Переполнение очереди считается и пишется в консоль, бот не падает.
- **D-403. Приватность**: содержимое не логируется из `⚫┃совет`, `⚖️┃суд-и-допуски`, `📊┃логи`,
  веток внутри них и из каналов категории `🎫 ТИКЕТЫ` — только факт. В БД содержимое не хранится.
- **D-404. Защита от петли**: удаления/правки в `#логи` и сообщения ботов не логируются; ошибки
  доставки логов пишутся только в консоль.
- **D-405. Правки**: логируются только настоящие правки людей (есть `edited_timestamp`), подгрузка
  превью ссылок игнорируется. Без Message Content Intent — пометка «содержимое недоступно».
- **D-406. Создание/удаление каналов тикетов** в логи сервера не пишется (это отдельные события
  бота «тикет открыт/закрыт»), чтобы не дублировать.
- **D-407. Пригласивший** определяется сравнением счётчиков приглашений (нужно «Управление сервером»;
  без него поле просто не показывается).
- **D-408. Категории** `/logs toggle`: members, roles, messages, server, voice (по умолчанию выкл.), bot.
  Предупреждения и ошибки бота отправляются всегда.

## Фаза 5 — защита

- **D-501. Граница окна рейда**: учитываются входы, у которых `now - ts < T` (строго). 8 входов
  за 19,9 с — локдаун; если между первым и восьмым ровно 20 с — нет.
- **D-502. Приостановка приглашений.** Проверено интроспекцией: в discord.py 2.7 `Guild.edit`
  принимает `invites_disabled` и `verification_level`. Локдаун ставит `invites_disabled=True`
  и уровень проверки «Высокий», прежние значения хранятся в `raid_state` и возвращаются при снятии.
  Нужно право «Управление сервером»; без него локдаун работает (тайм-ауты), а в оповещении
  написано, что настройки сервера не изменены.
- **D-503. Авто-снятие** — через 15 минут после последнего всплеска (новый всплеск продлевает).
- **D-504. Фильтры входа** — скоринг (новый аккаунт +2, аватар по умолчанию у свежего +1, ссылка
  в нике +3, шаблонный ник +2). Аккаунт моложе 24 ч или скоринг ≥ 3 → тайм-аут 30 минут и пометка
  в логах. Никаких банов.
- **D-505. Ссылки в `#приём-материалов` разрешены** (шаблон приёма прямо просит ссылку на
  доказательства), приглашения на другие серверы — нет. В остальных каналах для ролей ниже
  Доверенного — только домены из `ALLOWED_SITE_DOMAINS` и CDN Discord.
- **D-506. Серия сообщений** (флуд) — нарушение засчитывается не чаще раза в 3 с, остальные
  сообщения серии просто удаляются, чтобы лестница не прыгала сразу на час.
- **D-507. Anti-nuke** реагирует на события журнала аудита. Деструктивные действия: удаление канала,
  удаление роли, бан, кик, создание вебхука, смена прав `@everyone` (роль или оверрайт канала).
  `prune` (массовый кик) считается сразу за срабатывание. Исключения: владелец сервера, роль
  Основателя, сам бот. Совет **не** исключён (как в ТЗ): во время рейда массово кикать лучше
  кнопкой бота «Кикнуть вошедших во время рейда».
- **D-508. Ответ anti-nuke**: снимаются роли с опасными правами ниже роли бота (снимок в
  `role_snapshots`, вид `nuke`), тайм-аут 24 ч, оповещение Совета и ЛС владельцу. Удалённое не
  пересоздаётся. Боты-интеграции: управляемую роль снять нельзя — только оповещение.
- **D-509. Пороги** `/raid config <секция.параметр> <значение>` — секции `raid`, `spam`, `nuke`;
  хранятся в таблице `settings` с префиксом `cfg.` и переживают перезапуск.

## Фаза 6 — иерархия и наказания

- **D-601. Ранги взаимоисключающие.** `/rank set` снимает все прочие ранговые роли (кроме роли
  Основателя) и выдаёт одну. Лестница `promote/demote`: Незнакомец → Последователь → Посвящённый →
  Доверенный → Член Совета → Глава; Архивариус назначается через `/rank set`, понижение Архивариуса —
  в Посвящённого.
- **D-602. Кто может снять текущую роль.** Чтобы понизить человека, нужно иметь право и выдать
  новую роль, и снять текущую (например, снять Доверенного может только Совет+).
- **D-603. Лжец и ранги.** Лжецу нельзя выдать ранг выше Последователя, Отлучённому — никакой, пока
  метку не снимут `/restore`. Человек с меткой сам не распоряжается допусками.
- **D-604. Снимки ролей** хранятся ключами ролей (`["INIT","TRUST"]`), а не ID: после пересоздания
  роли `/setup` восстановление продолжит работать. `/restore` возвращает объединение снимков
  `liar` и `exile`, пропуская роли, которых больше нет на сервере; без ранга человек получает
  Незнакомца.
- **D-605. `/restore` не может вернуть роль ≥ ранга того, кто восстанавливает.**
- **D-606. Предупреждения** выносят Доверенные и выше; на третьем — подсказка в `#совет` с лестницей.
  `/warns` показывает последние 15 записей из `sanctions` (включая авто-тайм-ауты анти-спама).
- **D-607. Активность** копится в памяти и сбрасывается в БД раз в минуту (и при выгрузке модуля):
  только `user_id`, день (UTC) и число сообщений.
- **D-608. Владелец сервера неприкосновенен**, как и все, чья верхняя роль не ниже роли бота
  (Discord не даст их менять — бот сразу отвечает понятным отказом).

## Фаза 7 — мост с сайтом

- **D-701. API в том же процессе**, что и бот (uvicorn как задача asyncio, без перехвата сигналов):
  обработчики вызывают бота напрямую, без межпроцессного обмена. Если `API_TOKEN` пуст или короче
  16 символов — API не запускается, бот работает.
- **D-702. `discord_id` в ответе — строкой** (ID больше 2^53, JavaScript потеряет точность).
- **D-703. `roles` — машинные имена** (`follower`, `liar`…), а не названия с эмодзи: названия
  ролей можно менять, API от этого не сломается.
- **D-704. Для отсутствующих на сервере** `is_liar`/`is_exiled` берутся из БД, чтобы сайт видел метки
  и после выхода человека.
- **D-705. Ссылки** — только `https://`, домен строго из `ALLOWED_SITE_DOMAINS` или его поддомен
  (`evilveritas.example.com` не пройдёт для `veritas.example.com`), без `user:pass@`. Пустой список
  доменов = все ссылки запрещены.
- **D-706. Защита от передачи секретов**: схемы с `extra="forbid"` (нет полей для ключей), плюс
  отклонение текста, похожего на «пароль/ключ:/token=».
- **D-707. Лимит** — 60 запросов/мин на адрес клиента (за прокси uvicorn берёт адрес из
  `X-Forwarded-For` только от 127.0.0.1). Swagger/OpenAPI отключены.
- **D-708. `/archive announce`** доступна Архивариусу, Совету, Главе и Основателю (Доверенному — нет,
  хотя у него тоже допуск 4: публикация в архив — работа Архивариуса).

## Фаза 8 — полировка

- **D-801. `/status`** (Совет+): версия, аптайм, задержка, локдаун, открытые тикеты, анкеты
  в ожидании, состояние Message Content, очереди логов, API и ненайденных ролей.
- **D-802. Docker**: образ `python:3.12-slim`, бот работает не от root (uid 1000), поэтому папке
  `./data` на хосте нужен владелец 1000 (`sudo chown 1000:1000 data`). Порт API публикуется только
  на `127.0.0.1` хоста.
- **D-803. Лжец, перезашедший на сервер**, получает Незнакомца + Лжеца и может пройти ритуал входа
  заново (иначе он навсегда застрял бы без доступа). Метка при этом сохраняется.
- **D-804. Нет связи с Discord** при запуске — понятное сообщение вместо трассировки.
